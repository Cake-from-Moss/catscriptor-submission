# Спецификация акустического протокола

> **Примечание.** Шаблон рассчитан на задачу передачи данных по звуку. Наша задача — расшифровка
> разговоров, акустической передачи данных в ней нет. Заголовки шаблона сохранены, а документ описывает
> **протокол обмена данными приложения**: как аудио попадает на вход и в каком виде результат уходит
> наружу. Главная часть — строгий формат JSON из задания.

## Цели

- принять аудиозапись, обработать её на устройстве и выдать расшифровку со спикерами и временными метками;
- выдать результат в формате, который автоматически сравнивается с эталоном (WER, диаризация,
  таймкоды), без дополнительных обёрток и переименованных полей.

## Физический уровень

Вход: файл, выбранный пользователем через системный диалог `OpenDocument` (SAF), либо запись с
микрофона. Файл декодируется встроенными средствами Android (`MediaExtractor` + `MediaCodec`), поэтому
поддерживается любой формат, который декодирует устройство. Внутри конвейера аудио приводится к
**16 кГц, mono, PCM**. Запись с микрофона сохраняется как WAV PCM16 mono 16 кГц (≈1,92 МБ/мин).

Выход: файл, который пользователь сохраняет через системный диалог `CreateDocument` либо отправляет
через share sheet. Сетевой передачи нет.

## Формат передачи

### JSON (основной формат, строго)

```json
{"transcript": [{"speaker_id": "speaker_1", "start_ms": 1250, "end_ms": 4380, "text": "Добрый день!"}]}
```

| Поле | Тип | Правило |
|---|---|---|
| `transcript` | массив | единственное поле верхнего уровня; без дополнительных обёрток |
| `speaker_id` | строка | `speaker_N`, N — целое от 1, нумерация по первому появлению |
| `start_ms` | целое | миллисекунды от начала записи |
| `end_ms` | целое | миллисекунды от начала записи, `start_ms < end_ms` |
| `text` | строка | текст реплики (UTF-8) после LLM-коррекции |

Реплики отсортированы по `start_ms`. Временные метки относятся к репликам (интервал обработанного
фрагмента аудио), а не к отдельным словам. Схему проверяют JVM-тесты (`DefaultTranscriptExporterTest`);
JSON пишется UTF-8, метки — целыми числами. В JSON всегда `speaker_N`, пользовательские имена
спикеров не подставляются.

### Дополнительные форматы (для человека)

- **TXT:** название записи, пустая строка, затем строка на реплику: `[мм:сс – мм:сс] Спикер: текст`
  (для записей от часа `ч:мм:сс`). Можно подставлять имена спикеров.
- **SRT:** SubRip, нумерация с 1, `ЧЧ:ММ:СС,ммм --> ЧЧ:ММ:СС,ммм`, строка `Спикер: текст`, пустая
  строка между блоками.
- **ZIP:** файл расшифровки выбранного формата и исходное аудио без перекодирования.
- **Только аудио:** исходный файл записи.

## Установление и завершение передачи

1. Импорт: пользователь выбирает файл, приложение копирует его в приватный каталог и ставит
   обработку в очередь (foreground-служба).
2. Обработка: подготовка аудио → поиск речи → диаризация → распознавание → правка текста. Прогресс по
   стадиям доступен в UI.
3. Экспорт: пользователь открывает «Экспорт», выбирает формат и опции, затем «Сохранить» или
   «Поделиться». Экспорт разрешён только для готовой расшифровки, черновик ASR не экспортируется.

## Синхронизация

Единая шкала времени — миллисекунды от начала исходной записи. Все этапы конвейера работают в одной
шкале. Интервалы реплик берутся из VAD-сегментов и ходов спикеров; граница смены спикера смещается в
самую тихую точку (±0,4 с), чтобы не резать слово. Перекрытие реплик разных спикеров допустимо в модели,
но диаризация каждому моменту ставит одного спикера.

## Ошибки и восстановление

- Файл не удалось декодировать или он пуст — запись получает статус ошибки с сообщением, остальные записи
  не затрагиваются.
- Если LLM-правка сомнительна (потеря чисел или отрицаний, сильное расхождение с исходным текстом), в
  результат попадает исходный текст ASR. Спикеры и временные метки при этом не меняются.
- Если слияние не находит спикера для фрагмента, фрагмент не получает `speaker_1` «по умолчанию».
- При ошибке записи в выбранный документ провайдер может оставить частично записанный файл; приложение
  показывает ошибку, и сохранение можно повторить.
- Результаты и правки сохраняются атомарным снимком библиотеки.

## Совместимость

- Android 11+ (`minSdk 30`), только `arm64-v8a`.
- Вход: любой формат, который декодирует устройство (проверены WAV и M4A).
- Выход JSON соответствует ТЗ организаторов; для оценки качества рекомендуется нормализовать регистр,
  пунктуацию и «ё/е» на обеих сторонах (инструменты в `src/mobile/android/tools/evaluation`).

## Пример

JSON-экспорт короткого диалога:

```json
{"transcript": [
  {"speaker_id": "speaker_1", "start_ms": 1322, "end_ms": 2998, "text": "Привет, как твои дела?"},
  {"speaker_id": "speaker_2", "start_ms": 3594, "end_ms": 6966, "text": "О, привет! Мои дела хорошо."}
]}
```

(Пример показывает формат; тексты взяты из короткой тестовой записи команды, реальный вывод приложения
для конкретного файла может отличаться.)
