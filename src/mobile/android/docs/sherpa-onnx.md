# Issue #4: sherpa-onnx и упакованные модели

Исторические результаты ниже относятся к #4. Текущее состояние #5, Silero VAD,
production backend с интервалами фрагментов и отдельный необязательный CTC-прототип:
[vad-asr.md](vad-asr.md). Упоминания блокера границ слов ниже — история #4,
а не актуальное требование: ТЗ требует таймкоды реплик, не слов.

## Решение

Используется официальный `sherpa-onnx-2.0.1.aar` из
[релиза v2.0.1](https://github.com/k2-fsa/sherpa-onnx/releases/tag/v2.0.1).
SHA-256: `a8d09d1d32f3eb8520482c6d3d43fae674681c5b050385967c70a3c2c9bf0ee7`.
Проверены и исходники Kotlin API тега, и сигнатуры классов внутри скачанного AAR.
Нативные библиотеки имеют ELF-выравнивание LOAD 16 КБ. Проект по-прежнему собирает
свой `libcatscriptor.so` NDK 28.2.13676358 / CMake 3.22.1 / C++17; sherpa не
связывается с этим шаблонным JNI. Официальный JNI загружается лениво самим AAR.

| Критерий | Готовый AAR (выбран) | Исходники |
|---|---|---|
| Интеграция | Локальная файловая зависимость с проверкой SHA-256 | Сборка sherpa, ORT и зависимостей |
| Поддержка GigaAM v3 | Готовые CTC и NeMo Transducer API | Те же API, возможность патчей |
| Память | Явные release recognizer и stream | Дополнительно настройка/изменение движка |
| Размер | Есть неиспользуемые C/C++ API | Можно отключить лишние компоненты |
| Воспроизводимость | Один фиксированный артефакт | Нужна фиксация всей цепочки сборки |
| Release-риски | JNI, R8, ABI, упаковка | Дополнительно линковка и совместимость toolchain |

Для #4 сборка из исходников не требовалась. В #5 добавлена отдельная диагностическая
сборка с доступом к исходным CTC logits; официальный AAR не изменяется.

## Подтверждённые варианты GigaAM v3

В [официальном asr-models](https://github.com/k2-fsa/sherpa-onnx/releases/tag/asr-models)
есть четыре архива от 2025-12-16:

| Архив (префикс `sherpa-onnx-nemo-`) | API | Размер архива, байт |
|---|---|---:|
| `ctc-giga-am-v3-russian-2025-12-16.tar.bz2` | `OfflineModelConfig.nemo` | 163286197 |
| `ctc-punct-giga-am-v3-russian-2025-12-16.tar.bz2` | `OfflineModelConfig.nemo` | 163282594 |
| `transducer-giga-am-v3-russian-2025-12-16.tar.bz2` | `transducer`, `nemo_transducer` | 167388020 |
| `transducer-punct-giga-am-v3-russian-2025-12-16.tar.bz2` | То же | 170197019 |

CTC требует `model.int8.onnx` и `tokens.txt`; Transducer — `encoder.int8.onnx`,
`decoder.onnx`, `joiner.onnx`, `tokens.txt`. Варианты punct экспортируются из
`v3_e2e_ctc` / `v3_e2e_rnnt`, поддерживают пунктуацию и нормализацию текста.
Скрипты экспорта и специальные метаданные доступны в
[scripts/nemo/GigaAM](https://github.com/k2-fsa/sherpa-onnx/tree/v2.0.1/scripts/nemo/GigaAM).
Готовым архивам конвертация не нужна; произвольный upstream ONNX без этих
метаданных не считается совместимым. Не все страницы сайта sherpa обновлены до v3.

Для #4 выбран CTC без пунктуации: один граф, символьный словарь и минимальная
инфраструктура. Локальная LLM-коррекция остаётся обязательным последующим этапом.
Только этот CTC-комплект скачан, проверен по SHA-256 и запущен на Android.
Остальные три варианта исследованы по официальным артефактам/экспортам, но не запущены.

## Подготовка и доступ к файлам

```bash
python3 scripts/prepare_models.py
./gradlew :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
./gradlew :app:assembleRelease
```

Скрипт использует только стандартную библиотеку Python. Манифесты:

- `app/src/main/assets/model-manifest.properties`: идентификатор комплекта, URL,
  SHA-256 архива и каждого обязательного файла; также хеш тестового WAV.
- `dependencies/sherpa-onnx.properties`: URL, версия и SHA-256 AAR.
- `dependencies/licenses.properties`: фиксированные источники и хеши лицензий.
- `app/src/main/assets/vad-manifest.properties`: обязательные Silero ONNX и MIT LICENSE.

Кэш загрузок — `.model-cache/`; AAR — `dependencies/`; модель —
`app/src/main/assets/models/gigaam-v3-ctc-int8-2025-12-16/`. Все бинарные артефакты
игнорируются Git. Повторный запуск проверяет содержимое перед пропуском загрузки.
Архив не распаковывается целиком: извлекаются только конкретные обычные файлы.
SHA-256 защищает от незаметной замены файлов в изменяемом релизе `asr-models`.

`verifyBundledModels` выполняется перед `preBuild` для Debug и Release, не скачивает
ничего и останавливает сборку при отсутствии/повреждении AAR, модели или лицензий.
Теперь проверяются комплекты ASR и VAD; это не проверка готовности диаризации/LLM.
Конфигурационный кэш Gradle поддерживается. Формат ONNX хранится без сжатия.

AssetManager официально поддерживается, но CTC-реализация читает весь граф в
дополнительный буфер. Поэтому используем файловый конструктор recognizer после
копирования в `noBackupFilesDir/models/<model.id>/`. Широких разрешений нет.
Внутрипроцессный монитор и файловая блокировка сериализуют подготовку, SHA-256
проверяется при каждом открытии этапа. Неизменённые файлы не копируются заново.
Повреждённая внутренняя копия восстанавливается из assets. Повреждённый asset
даёт `ModelPreparationException` с именем файла; публикация — через атомарное
переименование проверенного временного файла в том же каталоге. При ошибке/отмене
временный файл удаляется; предыдущий файл не заменяется непроверенным.

## Ресурсы и ошибки

`SherpaModelResource` реализует существующий `ModelResource`; изменения контрактов
`AudioDecoder`, `TranscriptionBackend` и JSON отсутствуют. Конструктор не грузит
модель. `diagnose()` работает на IO dispatcher, принимает только короткий PCM
16 кГц mono, CPU provider, два потока по умолчанию. Это не полноценный ASR-backend.
64 mel-признака соответствуют официальному экспорту GigaAM v3.

Владелец обязан использовать `use`/`finally` и закрывать ресурс после этапа, включая
ошибки и отмену. Stream освобождается внутри `finally`; recognizer освобождается
в `close()`. Закрытие повторяемое; после него вызовы запрещены. Один монитор
исключает гонку decode/close. `close()` выполнять вне UI: он может ждать decode.
Отмена проверяется между операциями и порциями копирования; синхронный JNI decode
и инициализация не прерываются посередине. Указатель не освобождается до их окончания.
Следующий этап не должен загружать модель до закрытия предыдущего.

Неверные хеши/отсутствующие файлы отклоняются до JNI. Это не универсальный валидатор
ONNX: sherpa местами использует аварийное завершение при несовместимых метаданных.
Нельзя обещать Kotlin-исключение для любого нативного сбоя или нехватки памяти.
Новый комплект требует отдельной проверки совместимости и обновления манифеста.

## Размер и память

ONNX: 224721476 байт (214,3 МиБ). Для внутренней копии требуется ещё столько же
диска плюс небольшой запас под словарь и временное копирование при восстановлении.
В ARM64-части AAR: ORT 22249560, JNI 4609320, C API 4303136, C++ API 272848 байт.
Остальные ABI исключаются `abiFilters`. Модель вместе с этими библиотеками —
около 244,3 МиБ несжатых данных, без остального приложения и последующих моделей.

В первом smoke-прогоне `Debug.getNativeHeapAllocatedSize()` после decode составил
271101024 и 271149152 байт в двух последовательных открытиях. Это снимки занятой
нативной кучи, **не пик RAM/PSS и не доказательство отсутствия всех утечек**.
Для длинных записей обязательны сегменты; лимит 25 секунд здесь относится только
к диагностике и не является измеренным оптимальным размером ASR-чанка.

## Лицензии

sherpa-onnx — Apache-2.0; GigaAM v3 в выбранном архиве — MIT; ONNX Runtime 1.28.2 — MIT.
Лицензия модели поставляется рядом с ONNX. В `assets/third-party/` скрипт помещает
лицензии sherpa, ORT, kaldi-native-fbank, kaldi-decoder, utf8proc, simple-sentencepiece,
hclust, JSON и ThirdPartyNotices ORT. Их источники и хеши зафиксированы отдельно.
Это комплект уведомлений для интеграции; добавление новых моделей/движков требует
новой проверки лицензий. Тестовый WAV взят из того же официального архива, упакован
только в тестовый APK и не используется основным приложением.

## Проверки на телефоне

Устройство: vivo V2538, SoC SM7750, Android 16, ABI `arm64-v8a`.
Реальный smoke: два открытия CTC int8, два decode официального `example.wav`,
проверка текста, токенных точек, повторного close и запрета повторного использования.
Первоначальные времена 3109/2918 мс включают подготовку/загрузку/decode, поэтому
не приводятся как RTF. Эталонная расшифровка не зашита в тест — проверяется
непустой русский текст и структура результата.

У приложения нет `INTERNET`; это проверяется и в тесте. Системные настройки связи
телефона не менялись. Тест не требует сети даже при первом запуске после установки.
Отдельная проверка release на устройстве не выполнена: APK не подписан.

```bash
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=org.cfm.catscriptor.native.models.SherpaModelSmokeTest
```

Gradle-проверки `testDebugUnitTest`, `lintDebug`, `assembleDebug`, `assembleRelease`
прошли. JVM: 25 тестов, включая контракты #1, экспорт #2 и 6 тестов подготовки
модели (копирование/повторное использование, повреждение, отсутствие, отмена,
конкурентный доступ, несовместимый манифест).

Отдельно проверены отрицательные сценарии сборки: без `tokens.txt` Debug APK
не собирается; при повреждении `tokens.txt` с сохранением размера Release APK
не собирается. После проверки исходные байты восстановлены. Проверено содержимое
обоих APK: только ARM64, ONNX без сжатия и с ожидаемым SHA-256, 9 файлов лицензий,
нет тестового WAV. Размеры на этой сборке: Debug 292664816 байт, Release unsigned
261995194 байт; это не бюджет готового оценочного APK со всеми моделями.

Сбой тестов #2 `NoClassDefFoundError: kotlin.jvm.internal.Intrinsics` исправлен:
`ExportTestProvider` перенесён из Kotlin в отдельный Java-файл только в `androidTest`.
Провайдер запускается в процессе тестового APK без classpath основного приложения,
а Kotlin stdlib исключается из тестового APK как уже имеющаяся в приложении.
Теперь провайдер зависит только от Android/Java API; production-код экспорта и
настройки зависимостей не менялись. Полный `:app:connectedDebugAndroidTest` на
vivo V2538 / Android 16 прошёл: 7 тестов, 0 ошибок, 0 пропусков, включая 5 проверок
экспорта и настоящий ASR smoke-test.

## Следующие #5 и #12

`OfflineRecognizerResult.timestamps` — моменты эмиссии символов/токенов; CTC greedy
decoder не возвращает конечные границы. `durations` применимы к TDT, `words` —
идентификаторы HLG, а не интервалы слов. Поэтому результат диагностики намеренно
не преобразуется в `TimedWord` и не подключён к `TranscriptionBackend`.

Нужно проверить достоверное получение обеих границ слова, при необходимости
добавить forced alignment. Нельзя равномерно делить интервал или переносить
возможности Python GigaAM `word_timestamps=True` на Android API без проверки.
Затем реализовать backend, абсолютные смещения сегментов, отмену и fallback,
сравнить четыре v3-варианта по WER/RTF на телефоне, измерить пик RAM и выбрать
длину сегмента/число потоков. LLM меняет текст, но не исходные ASR-интервалы.
