# Запись микрофона (#21)

Основная сборка записывает микрофон через один Android `AudioRecord`: WAV PCM16,
моно, 16 кГц, 1,92 МБ/мин. Разрешение `RECORD_AUDIO` запрашивает существующий
экран; без разрешения или доступного микрофона запись не начинается.

1. Откройте главный экран и разрешите доступ к микрофону.
2. Начните запись. Пауза исключается из таймера; отметки используют время
   записанного аудио, а не время, проведённое на паузе.
3. Нажмите «Стоп»: контейнер завершается, файл передаётся в существующую очередь
    через `ProcessingController.importFile()`. Идентификатор возвращает очередь.
4. «Отменить запись» открывает подтверждение. «Продолжить запись» ничего не удаляет;
   «Удалить запись» закрывает микрофон и модели, удаляет текущий файл без импорта.
   Это не обычное удаление из библиотеки и у него нет Undo.

В обеих лентах свайп влево только раскрывает кнопку «Удалить». Удаление скрывает
запись на 5 секунд с Undo; после окна отмены освобождаются проигрыватель/обработка,
удаляется принадлежащий приложению WAV и запись атомарного снимка. Внешний SAF-файл
никогда не удаляется. Tombstone переживает перезапуск и повторяет незавершённую очистку.

Файлы находятся в приватном `filesDir/recordings/`, а не во временном кеше.
`FileProvider` открывает только этот каталог и выдаёт локальный `content://` URI:
его может читать существующий `AndroidAudioDecoder` в процессе приложения,
включая сервис обработки. Разрешения на общее хранилище не нужны.

## Пользовательские пометки

Пометка — отдельные пользовательские метаданные: идентификатор, позиция аудио в
миллисекундах и необязательный текст до 2000 символов. Пустой текст означает обычную
временную отметку. Пометки можно добавлять во время записи, в том числе с Live,
а после обработки — добавлять, редактировать и удалять на экране расшифровки.

Время пометки при записи берётся из сохранённого аудио: пауза его не увеличивает.
Для текстовой пометки фиксируется момент открытия редактора, а не окончания набора.
При «Стоп» пометки передаются записи библиотеки и сохраняются в атомарном снимке;
отмена записи удаляет также её пометки. Пометки готовых записей переживают
перезапуск. Старые снимки без этого поля загружаются с пустым списком пометок.
Ни распознанные реплики, ни их таймкоды, ни строгий JSON экспорта не изменяются:
личные пометки не включаются в экспорт расшифровки.

## Live и ограничения

- Микрофон сопровождается отдельным foreground service с уведомлением.
  Смерть процесса не восстанавливает незавершённый WAV автоматически.
- Live использует Silero и тот же GigaAM на фрагментах до 8 секунд. Это offline-ASR
  по коротким фразам, не пословные промежуточные гипотезы. Спикер нейтрален, время
  взято из сэмплов сохранённого PCM; паузы и пропуски очереди не склеиваются.
- Входная очередь ограничена 32 блоками по 512 сэмплов, очередь ASR — двумя
  фразами; история UI — 200 строками. Перегрузка пропускает только preview,
  никогда не блокирует сохранение аудио. Ошибки показываются как ошибки, без заглушек.
- Выключение Live отменяет ветку и освобождает модели. Синхронный JNI decode
  нельзя прервать мгновенно: освобождение ждёт возврата текущего вызова.
- Финальная обработка имеет приоритет: отзывает Live и ждёт закрытия моделей;
  после «Стоп» запускается прежний VAD → CAM++ → ASR → LLM, без изменения JSON.
- Индикатор показывает пик PCM последнего блока в dBFS, не RMS и не результат VAD.
- Перед началом и во время записи проверяется резерв свободного места 5 МиБ.
  При его исчерпании контроллер пытается завершить контейнер и освобождает
  микрофон. Завершённые файлы сохраняются и при отказе очереди; автоматического
  восстановления/повторного импорта таких файлов пока нет.
- Системная блокировка микрофона может давать тишину вместо ошибки Android.
  Нулевая амплитуда не выдаётся за результат Silero VAD.

## Проверка

JVM-тесты: `RecordingControllerTest`, `HomeViewModelTest`.
Android-тесты записи находятся в пакете `org.cfm.catscriptor.recording`;
для проверки микрофона нужен доступный Android-телефон с выданным разрешением.
Бинарные пользовательские записи в репозиторий не добавляются.

Общая проверка сборки и JVM-тестов:

```bash
./gradlew assembleDebug assembleRelease test :app:assembleDebugAndroidTest
```

После установки debug APK и test APK:

```bash
adb shell am instrument -w -r \
  -e class org.cfm.catscriptor.recording.RecordingFileProviderTest \
  -e recordMicrophone true \
  org.cfm.catscriptor.test/androidx.test.runner.AndroidJUnitRunner
```

Аргумент `recordMicrophone=true` явно разрешает тесту использовать микрофон;
без него микрофонная проверка пропускается. Тест выдаёт разрешение через shell,
открывает Activity, записывает с паузой и декодирует WAV. Отдельная интеграционная
проверка заменяет только источник аудио готовым тестовым M4A, но использует
настоящие `stop → importFile → AudioProcessingService → AndroidAudioDecoder`
и проверяет успешное завершение подготовки аудио.

Проверено 07.11.2026:

- `assembleDebug assembleRelease test :app:assembleDebugAndroidTest --offline` —
  успешно; JVM: 132 теста, из них 1 пропущен, ошибок нет.
- vivo V2538, Android 16 / API 36, arm64-v8a: все 3 Android-теста прошли
  с `recordMicrophone=true`, включая настоящую запись с паузой и возобновлением,
  чтение через FileProvider и передачу файла сервису обработки.
- Фоновая запись и восстановление после смерти процесса не проверялись
  и не входят в гарантии этой версии.
