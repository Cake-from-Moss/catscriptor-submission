## Непроверенное и ограничения

- Выполнена перекрёстная проверка DER с pyannote.metrics; точные правила судей неизвестны.
- WER линейный по порядку начала реплик, не решает неоднозначность порядка overlap.
- Оценка границ one-to-one; split/merge отражается unmatched, не many-to-many.
- Нет пословных эталонов и пословной оценки.
- Память, Android RTF и точность полного пайплайна не измерены.
- Android-сборка здесь не запускалась: Android-код не изменён, задача проверена
  Python-тестами, а не заявлением о работоспособности APK.

## Финальное ревью инструментария

- Критический дефект защиты входов: hardlink позволял перезаписать эталон
  отчётом. Исправлено проверкой идентичности файлов; регрессионный тест сначала
  воспроизвёл дефект, затем прошёл. Проверка symlink/совпадающих путей сохранена.
- Существенный дефект: конечные входные числа могли дать Infinity RTF и stack
  trace при JSON-выводе. Теперь конечность результата проверяется, переполнение
  агрегата даёт exit code 2; добавлены регрессионные тесты.
- Незначительные замечания: добавлены тип реплики/аннотации ключевых функций,
  явная UTF-8 кодировка файлов и консоли, условные pinned-зависимости для Python
  3.10/Windows, coverage границ в текстовом выводе. Тест с ASCII-кодировкой
  перенаправленной консоли проходит; реальные Windows/Linux отдельно не запускались.
- Архитектура разделяет CLI, схему, нормализацию, метрики, matching и отчёт.
  Обязательных тяжёлых зависимостей нет; pyannote проверяется в отдельном venv.
- Математических расхождений после согласования support/collar с pyannote
  не осталось; неопределённые доли при пустом эталоне описаны явно.

Ручная сверка WER (S/D/I/N): `кот спит` → тот же текст: 0/0/0/2 (0);
→ `кот ест`: 1/0/0/2 (0.5); → `кот`: 0/1/0/2 (0.5);
→ `кот уже спит`: 0/0/1/2 (0.5); `Ёжик, кот!` → `ежик кот`: 0/0/0/2 (0);
пустой эталон → `кот`: 0/0/1/0 (null).

Ручная сверка DER (все времена в мс): пропуск [0,1000) даёт miss=1000/1000;
лишняя секунда после правильной даёт FA=1000/1000; один предсказанный спикер
на двух последовательных эталонных по 1000 даёт confusion=1000/2000.
Эталон A:[0,1000), B:[500,1500), гипотеза только A даёт miss=1000/2000.
Эталон [100,900), гипотеза [0,1000), collar ±100 даёт total=600, ошибок нет.
Самоперекрытие одного спикера [0,1000), [500,1500) считается как total=1500,
а не 2000. Все ожидания совпали с запуском реализации.
