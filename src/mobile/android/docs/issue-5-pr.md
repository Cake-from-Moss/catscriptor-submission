# Черновик PR issue #5 в dev

## Актуализация требований

ТЗ требует таймкоды **реплик**, не слов. Обязательные `TimedWord` и forced alignment
отменены как ошибочное архитектурное решение. Текущая реализация переводит контракты
на `AsrSegment(time, text)` и `Utterance` без обязательных слов, добавляет настоящий
`TranscriptionBackend` поверх существующей GigaAM, сохраняет JSON и opt-in CTC-прототип.
VAD-интервал не равен реплике одного спикера: уточнение интервалов и повторное
распознавание speaker turns относятся к #6. По дополнительному запросу UI
подключён к реальному VAD → ASR; оценочные файлы #11 не входят в scope.

Критерий #5 проверен на vivo V2538 / ARM64 / Android 16: реальный production
VAD → GigaAM без word alignment. JVM: 113 пройдены, 1 пропущен; Android:
24 пройдены, 4 пропущены (все 5 speech smoke прошли). Debug/Release собраны.
Lint по-прежнему падает на `ScopedViewModelStore.kt:41`, без подавления.
Пример: `[11146,13110)` мс → «у лукоморья дуб зеленый». Стыки порций по 25 с
могут обрывать слова; WER/RTF/peak RAM не измерены. Подключение UI выдаёт только
черновик ASR без выдуманных спикеров и без экспорта; полная оркестрация с
диаризацией #6 и обязательной LLM #7 остаётся отдельной задачей.

После wiring повторные проверки: JVM **119 passed / 1 skipped**; Android
**25 passed / 4 skipped**, включая новый production-graph import E2E.
Debug и Release собраны; lint блокируется только известной исходной ошибкой.
Новый APK установлен на vivo V2538. Обычный SAF-импорт через системный picker
показал реальный русский текст и интервалы на экране черновика.
Хранение пока только в памяти процесса. Подробности: [vad-asr.md](vad-asr.md).

## Что не реализовано и почему #5 остаётся открытой

- Нет полноценного `TranscriptionBackend`, подтверждённых пословных интервалов,
  чанкинга длинной речи и удаления дубликатов на стыках.
- CTC alignment подтверждает занятые кадры, а не акустические границы слов.
  Независимая ручная разметка и ошибка границ пока отсутствуют.
- Полный pipeline не подключён. Статус `Ready` после подготовки PCM — открытая
  интеграционная проблема #8/#9, не скрытая этим PR.
- Пик RAM, скорость/RTF и качество на оценочных записях не измерялись.
- Диаризация #6 и обязательная локальная LLM #7 остаются отдельными этапами.

Экспорт, контракты, UI, `ProductionAppGraph`, `PipelineProcessingController`
и файлы оценки второго разработчика не менялись.

## Отдельная задача: русский forced alignment на Android

**Цель:** выровнять текст GigaAM по исходному PCM и вернуть подтверждённые
начало/конец слов без равномерного распределения или скрытой интерполяции.

Qwen3-ForcedAligner-0.6B функционально подходит по заявленной поддержке русского,
но не утверждён к интеграции: официальные веса около 1,71 GiB, Android CPU-путь
не подтверждён, а официальный постпроцессинг может интерполировать границы.
Whisper DTW и Vosk grammar не являются штатными aligner для внешнего GigaAM-текста.
Проверенные источники и точные ограничения — в [vad-asr.md](vad-asr.md).

Перед production-интеграцией нужны:

1. Согласование конкретной модели, лицензий, размера APK и runtime; GigaAM и
   экспорт не заменяются автоматически.
2. Численная проверка переноса/квантизации относительно официального runtime.
3. ARM64 CPU-прогон без сети с ограниченной памятью и последовательной выгрузкой
   ASR перед загрузкой aligner; замер пика RAM и скорости на телефоне.
4. Независимая ручная русская word-boundary разметка: паузы, короткие междометия,
   длинные слова, пунктуация, ненулевое смещение, границы чанков и ошибки ASR.
5. Согласованный допустимый уровень ошибки; неподтверждённые/немонотонные границы
   должны давать явную ошибку, а не вымышленные `TimedWord`.
6. После подтверждения метода — реализация существующего backend-контракта,
   чанкинга, отмены и проверки отсутствия слов за границами сегмента.

Эта задача пока только описана локально: новый GitHub issue не создавался,
веса aligner не скачивались, архитектурный перенос не начинался.

### Уточнение после повторного исследования

Предпочтительный следующий эксперимент — **текущий GigaAM CTC**, а не перенос
новой модели. Отсутствие измерений не доказывает непригодность CTC; оно означает,
что строгие требования к началу/концу слов пока не подтверждены. Официальные
GigaAM word timestamps тоже группируют эмиссии, а не оценивают края отдельной моделью.
VoiceScribe на commit `8add4d8` экспортирует segment timestamps. В whisper.cpp
`727d3e7` обычные token timestamps могут пропорционально заполнять неизвестные
интервалы; экспериментальный DTW даёт точки `t_dtw`. Ни один из этих фактов
не обосновывает миграцию Catscriptor на Whisper. Источники и план измерений —
в [vad-asr.md](vad-asr.md#продолжение-исследования-gigaam-voicescribe-и-whisper).

В начале продолжения телефон на порту 5038 был недоступен; затем пользователь
подключил его и подтвердил отсутствие независимой пословной разметки.
Сравнение начала/конца, WER/RTF, peak RAM и реальный Whisper-прогон **не выполнены**.
После подключения выполнен новый полный Android-прогон на официальном AAR:
**23 пройдены, 4 пропущены, 0 failures**. Лог:
`/tmp/opencode/issue-5-continuation-android-full.log`.
Отдельный новый CTC smoke также прошёл **4/4**: лог
`/tmp/opencode/issue-5-continuation-android-ctc.log`. Официальный APK восстановлен
на телефоне после проверки прототипа. Эти прогоны подтверждают выполнение,
но **не** акустическую точность начала/конца слов и не отсутствие всех утечек.

Повторные локальные проверки продолжения: JVM **107 пройдены, 1 пропущен**
(108 всего), Debug/Release и AndroidTest APK собраны. Lint снова блокируется
`ScopedViewModelStore.kt:41`; отчёт сохранён, подавления не добавлены.
Логи: `/tmp/opencode/issue-5-continuation-{gradle,lint}.log`.
Модели в Debug/Release проверены по SHA-256, ONNX не сжаты, ABI только ARM64,
тестового WAV нет. **#5 по-прежнему не готова:** production backend и проверенные
`TimedWord` отсутствуют; фиктивная реализация вместо них не добавлялась.
