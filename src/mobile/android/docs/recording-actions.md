# Действия с готовой записью

- Название в интерфейсе и системном меню приложений — **CatScriptor**; идентификатор
  пакета `org.cfm.catscriptor` не менялся, обновление сохраняет прежние данные.
- На главном экране в последних записях и в библиотеке свайп **вправо** раскрывает
  кнопку переименования. Она открывает диалог с текущим названием. Пустое название
  недопустимо, пробелы по краям убираются. Свайп **влево** по-прежнему раскрывает
  удаление; ни один жест сам по себе запись не удаляет.
- «Пунктуация и правка» включаются переключателем в настройках для первичной
  обработки. По умолчанию переключатель включён; его выключение не меняет уже
  готовые записи. Без этого этапа запись всё равно становится готовой и доступна
  для экспорта.
- Для готовой записи, ещё не прошедшей коррекцию, пункт доступен в контекстном меню.
  Перед запуском требуется подтверждение. После успешной коррекции пункт исчезает;
  постоянной отдельной кнопки правки моделью нет.

Настройка сохраняется между запусками. Её значение фиксируется при начале обработки
очередной записи: переключение во время уже работающего конвейера не меняет этот запуск.
Live-предпросмотр — отдельная настройка, переключатель коррекции на него не влияет.

## Отложенная пунктуация и правка

В локальном атомарном снимке хранится `textCorrected`. Это метка успешного
прохождения модельного этапа, а не эвристика по наличию знаков препинания.
Она устанавливается только после успешного завершения и сохранения всего результата,
в том числе когда защита корректора оставила текст без изменений. Ошибка или отмена
не устанавливают метку. Переименование, пометки и ручная правка текста её не сбрасывают.
Старые снимки без этого поля загружаются со значением `false`: достоверной истории
прохождения этапа для них нет, поэтому доступен один явный запуск.

`ProcessingController.correctText` запускает существующий foreground service
в режиме `CORRECT_TEXT`. Используется прежняя bundled LLM и прежний защитный
`CorrectionGuard`; декодер, VAD, диаризация и ASR не запускаются. Исходное аудио
для этого действия не требуется: можно исправить текст старой готовой записи,
даже если доступ к импортированному документу уже утрачен.

На вход поступает **текущий видимый текст**, включая ручные правки. Результат может
изменить его пунктуацию, регистр и распознанные слова в пределах защиты корректора.
Отклонённая модельная правка может оставить реплику без изменений; идеальная
пунктуация не гарантируется. Спикеры и интервалы реплик не меняются.

Сервис сериализован с полным конвейером через общий `ModelExecutionGate`. Если уже
идёт другая обработка, действие сообщает, что нужно дождаться её завершения.
Live-модель освобождается перед загрузкой LLM; микрофонная запись при этом продолжается.

Старый готовый документ остаётся доступен во время коррекции. Новый текст
публикуется и записывается атомарно только после успешной обработки всех реплик
и закрытия модели. При ошибке, отмене или завершении процесса старый документ
не теряется. Переименование, имена спикеров и пометки сохраняются. Если пользователь
параллельно изменил текст или назначение спикера, коммит отклоняется с предложением
повторить действие — чужие изменения не затираются. Отдельной истории версий или
отмены уже завершённой коррекции пока нет.

Формат JSON не менялся: экспортируется только массив `transcript` с полями
`speaker_id`, `start_ms`, `end_ms`, `text`; название и пометки в него не добавляются.

## Проверки

Актуальная проверка переключателя и метки: [отчёт](text-correction-option-validation.md).

- JVM: `TextCorrectionRunnerTest` — только изменение текста, пустой ответ модели,
  закрытие ресурса и отсутствие частичного результата при ошибке/отмене.
- JVM: `CorrectedTranscriptTest` — сохранность метаданных и исходного черновика,
  правка видимого пользовательского текста, отказ при конфликте/удалении/смене интервала.
- JVM: `PipelineRecordingRepositoryTest` — переименование без изменения остальных
  полей и отказ от пустого названия.
- Android: `RepeatTextCorrectionTest` — настоящий сервис и bundled GGUF, недоступный
  аудио-URI, параллельное переименование и повторная загрузка атомарного снимка.
